# 영상 콘티

## 기획 방향

먼저 **“어텐션과 MLP의 반복”**이라는 지도를 주고, 곧바로 코드에서 그 두 줄을 찾아줍니다. 시청자가 이후 설명을 어디에 붙여야 할지 알게 하는 구성입니다.

이 저장소를 활용하는 영상의 강점은 **방금 설명한 구조가 실제로 학습되는 코드에 그대로 있다는 것을 보여줄 수 있다는 점**입니다. 쉽게 설명하는 데서 시작해, 영상 끝에는 실제 코드를 읽을 수 있게 만드는 것을 목표로 합니다.

## 1. 두 부품은 역할을 대비해서 설명하기

도입에서 사용할 설명은 다음처럼 짝을 맞춥니다.

> 어텐션은 앞에서 나온 정보 중 무엇을 얼마나 가져올지 정합니다.
> MLP는 그렇게 모인 정보를 각 자리에서 가공합니다.

화면에는 더 짧게 표시합니다.

- **어텐션: 다른 자리에서 정보 가져오기**
- **MLP: 내 자리에서 정보 가공하기**

“문장의 주변을 본다”만으로는 무엇을 가져오는지 모호합니다. 또한 이 모델은 다음 글자를 예측하는 인과적 모델이므로 뒤쪽 글자는 볼 수 없습니다.

실제 코드에서도 어텐션은 위치 사이의 정보를 섞고, MLP는 각 위치의 벡터에 같은 신경망을 적용합니다. MLP가 다음 글자를 혼자 결정하는 것은 아니며, 최종 예측은 블록들을 지난 뒤 출력 행렬에서 합니다.

시각적으로는 **어텐션에서만 글자 사이에 화살표가 오가고, MLP에서는 각 글자의 상자 안이 변하는 모습**으로 차이를 전달합니다.

## 2. 도입의 약속

“쉽습니다”라는 말의 자신감은 살리되, 코드 읽기의 시작점을 알려준다는 약속을 분명히 합니다.

### 도입 문안 A

> 트랜스포머 코드를 이해하고 싶으신가요? 어디부터 읽을지는 간단합니다. 두 가지부터 보세요. 어텐션과 MLP.

### 도입 문안 B

> 트랜스포머 코드, 복잡해 보이죠? 우선 두 가지만 찾으세요. 어텐션과 MLP입니다.

첫 1분의 목표는 모든 것을 이해시키기보다, **코드를 읽기 시작할 수 있게 하는 것**입니다.

## 3. 첫 1분 콘티

시간은 실제 낭독과 화면 호흡에 맞춰 조정합니다.

| 시간 | 내레이션 | 화면 |
|---|---|---|
| 0–7초 | “트랜스포머 코드를 이해하고 싶으신가요? 우선 두 가지만 찾으세요.” | 실제 코드가 보이다가 나머지가 흐려짐 |
| 7–12초 | “어텐션, 그리고 MLP입니다.” | 두 부품이 색을 달리해 등장 |
| 12–23초 | “어텐션은 앞에서 나온 정보 중 무엇을 얼마나 가져올지 정합니다.” | 현재 글자에서 앞쪽 글자들로 연결. 연결마다 굵기 차이 |
| 23–32초 | “MLP는 그렇게 모인 정보를 각 자리에서 가공합니다.” | 글자 사이 연결은 사라지고 각 자리의 벡터가 변함 |
| 32–39초 | “정보를 가져오고, 가공하고. 이 묶음을 여러 번 반복합니다.” | `Attention → MLP` 묶음이 네 층으로 쌓임 |
| 39–48초 | “여기에 입력과 예측, 정답을 보고 고치는 과정까지 놓으면, 학습 한 스텝의 흐름은 열 줄입니다.” | README의 열 줄을 한 화면에 표시 |
| 48–55초 | “방금 말씀드린 두 부품이 바로 이 두 줄이고요.” | `blk.attn(...)`, `blk.mlp(...)` 두 줄 강조 |
| 55–60초 | “그럼 이 `x`에는 무엇이 들어 있고, 두 줄을 지날 때 무엇이 달라질까요?” | `x`로 확대하며 본편 진입 |

마지막은 질문으로 끝냅니다. “이게 전부입니다”로 닫기보다 `x`의 정체를 열어두어 다음 내용으로 연결합니다.

### ‘열 줄’의 정확한 의미

열 줄은 **학습 한 스텝을 펼쳐 놓은 흐름**입니다. 실제 전체 구현은 123줄이며, 어텐션과 MLP의 내부 구현은 별도로 있습니다. 화면 제목은 **「학습 한 스텝, 열 줄」**로 둡니다.

```python
tokens, answers = get_batch()
optimizer.zero_grad(set_to_none=True)
x = wte[tokens] + wpe[:T]
for blk in blocks:
    x = x + blk.attn(layer_norm(x))
    x = x + blk.mlp(layer_norm(x))
logits = layer_norm(x) @ wue
loss = cross_entropy(logits, answers)
loss.backward()
optimizer.step()
```

위 코드는 README의 설명용 요약입니다. 실제 파일에서는 가운데 여섯 줄이 `Transformer.forward()` 안에 있고, 나머지 네 줄이 `train()`에 있습니다. 실행 코드의 함수 인자와 객체 참조는 [transformer.py](../transformer.py)를 따릅니다.

## 4. 코드를 계속 돌아오는 지도로 사용하기

처음부터 열 줄을 전부 읽어주기보다, 두 줄만 선명하게 남깁니다.

```python
for blk in blocks:
    x = x + blk.attn(layer_norm(x))
    x = x + blk.mlp(layer_norm(x))
```

이후 본편에서 설명이 끝날 때마다 같은 화면으로 돌아옵니다.

- 입력 설명 후: `wte[tokens] + wpe[...]`가 읽힘
- 어텐션 설명 후: `blk.attn(...)`이 읽힘
- MLP 설명 후: `blk.mlp(...)`이 읽힘
- 잔차 연결 설명 후: `x +`가 읽힘
- 학습 설명 후: `loss.backward()`와 `optimizer.step()`이 읽힘

**처음에는 낯설었던 코드가 영상 끝에는 읽히는 경험**을 영상의 보상으로 만듭니다. 어텐션과 MLP는 애니메이션에서도 코드에서도 같은 색을 유지합니다.

## 5. 본편은 ‘다음 글자 맞히기’라는 목표부터

첫 1분 이후에는 Q·K·V에 바로 들어가기보다, 모델이 하려는 일을 먼저 보여줍니다.

> 이 코드의 목표는 하나입니다. 지금까지 나온 글자를 보고, 다음 글자를 맞히는 겁니다.

이 저장소는 글자 단위 모델이므로 실제 코드와 맞춰 글자로 시연합니다.

```text
입력:  h e l l
정답:  e l l o
```

이 장면에서 이후 설명의 이유를 연결합니다.

- 왜 어텐션이 필요한가: 앞의 정보를 참고하려고
- 왜 뒤를 가리는가: 맞혀야 할 답을 미리 보면 안 되므로
- 왜 출력이 필요한가: 다음 글자 후보에 점수를 매기려고
- 왜 학습하는가: 정답 글자에 더 높은 점수를 주도록 바꾸려고

### 본편의 큰 흐름

**다음 글자 예측 → 글자를 벡터로 바꾸기 → 어텐션 → MLP → 반복과 `x +` → 예측과 학습 → 실제 생성 결과**

Q·K·V는 **“앞의 글자 중 무엇을 얼마나 가져올지 계산하는 방법”**으로 소개하여 도입의 설명과 연결합니다.

## 6. 후반의 반전: 한 줄 지우기

[try-this.md](try-this.md)의 마스크 제거 실험을 활용합니다. 미래를 가리는 마스크 한 줄을 지우면 손실이 오히려 크게 내려갑니다.

문서에 기록된 200스텝 실험에서는 학습 손실이 약 `2.54 → 0.74`로 내려갑니다. 예측을 잘해서가 아니라, 입력 안에 있는 정답을 볼 수 있게 되었기 때문입니다. 이 수치는 저장소에 기록된 실험 결과를 인용한 것입니다.

### 장면 문안

> 이 한 줄을 지우면 점수가 훨씬 좋아집니다.
>
> 그런데 모델이 더 똑똑해진 걸까요?
>
> 아닙니다. 정답을 미리 볼 수 있게 된 겁니다.

이 장면은 도입의 **“앞에서 나온 정보만 가져온다”**를 회수하면서, 코드 한 줄의 필요성을 체감하게 합니다. 실제 생성 결과와 함께 후반의 보상으로 활용합니다.

## 중심 문장

> 어텐션으로 앞의 정보를 가져오고, MLP로 각 자리에서 가공합니다. 트랜스포머의 중심은 이 두 동작의 반복입니다. 코드에서 찾아볼까요?

**두 가지 → 두 역할 → 반복 → 실제 코드의 두 줄**이라는 연결을 유지합니다. 도입에서 약속한 구조를 본편에서 실제로 읽히게 만드는 것이 이 콘티의 중심입니다.
